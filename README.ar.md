> **معاينة الهيكل v0.2:** [دليل الهيكل المعماري](docs/ARCHITECTURE.ar.md) · [English](docs/ARCHITECTURE.md). التشغيل عبر `python -m factory.architecture`، ويظل الأمر السابق مدعومًا.

[English](README.md) · [الأمان](SECURITY.md) · [خارطة الطريق](ROADMAP.md) · [المساهمة](CONTRIBUTING.md)

**الإصدار الأولي v0.1.0 من تصور V3 — ليس منصة استقلالية جاهزة للإنتاج.**

يضم المشروع جزأين مستقلين: مهارة قابلة للنقل إلى أدوات البرمجة الذكية، ومحرك Python يعمل فعليًا وفق مسار محدد: التخطيط ← إعداد المسودة ← المراجعة ← تسليم مسودة للمراجعة البشرية أو إيقافها عند الفشل. المهارة تصف الرؤية الواسعة، بينما ينفذ المحرك جزءًا صغيرًا منها.

## 1. تركيب المهارة في أدوات البرمجة

نزّل المستودع من رابطه الحقيقي بعد نشره، أو فك ضغط الحزمة. انسخ **المجلد كاملًا** `skills/ai-agent-factory/` إلى أحد المسارات التالية داخل مشروعك، دون استبدال مهارة قديمة قبل مراجعتها:

| الأداة | مسار المهارة داخل المشروع |
|---|---|
| Google Antigravity | `.agents/skills/ai-agent-factory/` |
| Codex | `.agents/skills/ai-agent-factory/` (تحقق من إصدارك) |
| Claude Code | `.claude/skills/ai-agent-factory/` |

افتح المشروع وحدّث قائمة المهارات أو أعد تشغيل الأداة عند الحاجة، ثم اكتب:

> استخدم مهارة ai-agent-factory لتصميم واختبار فريق يساعدني في نشر تطبيق Laravel. ابدأ بالقراءة فقط وقارن بوكيل واحد، واطلب موافقتي قبل التعديل.

يمكن استخدام `/ai-agent-factory` في Antigravity وClaude Code عندما تدعم الواجهة ذلك. في Codex اطلب المهارة بالاسم أو اخترها من واجهة المهارات. لا تحتاج المهارة نفسها إلى مفتاح API إضافي، لكن تخضع لاشتراك وأدوات وصلاحيات المضيف. لم نختبر اكتشاف المهارة داخل هذه التطبيقات عمليًا في هذا الإصدار.

## 2. تشغيل المحرك المرافق دون مكتبات خارجية

تحتاج Python 3.10 أو أحدث. افتح الطرفية **داخل المجلد الرئيسي للمشروع بعد فك الضغط**. لا تحتاج إلى تثبيت حزم أو مفاتيح API أو اتصال بالإنترنت في الوضع التجريبي.

```bash
python -m unittest discover -s tests -v
python -m factory run examples/task.ar.json
python -m factory run examples/task.en.json
```

إذا لم يعمل `python` في Windows جرّب `py -3`، وفي Linux/macOS جرّب `python3`. يظهر معرف التشغيل وتقرير JSON. تحفظ الملفات في `.factory-runs/<run-id>/`:

- `state.json`: الحالة والمدخلات والنتائج وسجل الأدوار.
- `report.json`: الحالة ودرجة المراجعة وعدد الطلبات والقيود.
- `draft.json`: المسودة عند اجتياز جميع المعايير وعدم رصد مشكلة حرجة، ولا تعتبر معتمدة نهائيًا.

الوضع التجريبي **حتمي وليس ذكاءً اصطناعيًا**؛ يحول المعايير إلى قائمة تحقق ويختبر وجود البنود نصيًا، ولا يدّعي تنفيذ الاختبارات المذكورة داخل القائمة.

## 3. التشغيل بنموذج محلي فعلي (اختياري)

ثبّت Ollama من موقعه الرسمي إذا رغبت، وشغّل الخدمة وثبّت نموذجًا محليًا مناسبًا. المشروع لا يثبّت أو ينزّل أي نموذج تلقائيًا. اعرض النماذج بالأمر `ollama list` واستبدل `YOUR_INSTALLED_MODEL` بالاسم الفعلي.

```bash
python -m factory --backend ollama --model YOUR_INSTALLED_MODEL run examples/task.ar.json
```

يتصل المحرك بالعنوان المحلي `http://127.0.0.1:11434/api/chat` فقط. لا يمنح النموذج أدوات تنفيذ ولا ينفذ مخرجاته كأوامر. الأدوار ثلاثة طلبات منفصلة بتعليمات مختلفة وليست عمليات متوازية أو نماذج مستقلة بالضرورة. إذا كانت الخصوصية مهمة فتأكد أن Ollama يشغل نموذجًا محليًا حقيقيًا وليس نموذجًا سحابيًا أو خدمة وسيطة. اختُبرت واجهة الاتصال بمحاكاة الاستجابات فقط، ولم يُشغّل نموذج حقيقي أثناء إعداد هذه النسخة. التشغيل المحلي يستهلك موارد الجهاز والكهرباء.

## 4. إضافة مهمة خاصة بك

انسخ أحد ملفات `examples` إلى مسار خاص، وعدّل الحقول: الهدف `goal`، والسياق `context`، واللغة `language` (ar أو en)، ومعايير النجاح `criteria` من 1 إلى 8 معايير فريدة قابلة للتحقق. لا تضع أسرارًا أو بيانات عملاء.

```json
{
  "goal": "إعداد قالب تقرير أسبوعي لتحسين محركات البحث",
  "context": "لا تتوفر بيانات تحليل حية؛ لا تخترع الأرقام",
  "criteria": ["إضافة حقول الزيارات العضوية", "تمييز البيانات الناقصة عن البيانات المقاسة"],
  "language": "ar"
}
```

```bash
python -m factory run path/to/task.json
python -m factory show RUN_ID
python -m factory resume RUN_ID
```

استبدل `RUN_ID` بمعرف التشغيل الحقيقي المؤلف من 32 حرفًا. عند استكمال تشغيل Ollama أعد كتابة خيارات النموذج والمزود قبل `resume`. خيار `--revisions` يقبل من 0 إلى 2 (الافتراضي 2). سقف الطلبات 3–7 حسب عدد الجولات، وتحسب المحاولات الفاشلة ضمن السقف. `--timeout` مهلة اتصال وليست سقفًا زمنيًا شاملًا. يستكمل المحرك من آخر مرحلة محفوظة، وقد يعيد طلبًا انقطع أثناء التنفيذ إذا بقيت ميزانية. التشغيل المحجوب نهائي؛ أنشئ مهمة جديدة بعد معالجة السبب. لا تحذف مجلد القفل `.lock` إلا بعد التأكد من عدم وجود عملية نشطة.

## 5. ما الذي يعمل وما الذي لم ينفذ؟

| الميزة | الحالة |
|---|---|
| المهارة ودليل عربي وإنجليزي | جاهزة، دون اختبار اكتشافها داخل المضيف |
| التخطيط والكتابة والمراجعة المتسلسلة | منفذة ومختبرة |
| تحديد عدد المحاولات وحفظ الحالة والاستكمال | منفذة ومختبرة |
| التشغيل التجريبي دون نموذج | تم تشغيله محليًا |
| ربط Ollama | اختبارات محاكاة؛ دون اختبار نموذج فعلي |
| بوابة الجودة | جميع المعايير إلزامية؛ تقييم النموذج استشاري لا يثبت الصحة |
| النشر التلقائي وإرسال الرسائل وتنفيذ الأوامر | غير منفذة |
| إنشاء الفرق الديناميكي والتوازي وتعدد المزودين والجدولة والذاكرة المؤسسية | إرشادات في المهارة أو خارطة طريق |

المحرك ينتج المسودات فقط. تعليمات المهارة ليست حاجزًا أمنيًا برمجيًا؛ فعّل ضوابط الصلاحيات في بيئة المضيف. اقرأ [سياسة الأمان](SECURITY.md) وراجع المخرجات قبل استخدامها.
